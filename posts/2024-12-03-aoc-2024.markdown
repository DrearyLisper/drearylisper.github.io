As the year winds down, it's time to refocus on some festive fun. Every December, the [Advent of Code](https://adventofcode.com/2024) challenge presents itself as an opportunity to take a break from daily responsibilities and explore coding in an entertaining way.

In previous years, I've taken on the challenge of solving all the problems using existing functional programming languages like Haskell, Ocaml, and Clojure - with varying degrees of success. While it's always been a fun and rewarding experience, this year I wanted to push myself even further.

<!--more-->

So, how do you take it to the next level after tackling 25 problems in Haskell? The answer is simple: by designing my own **programming language** from scratch and implementing a **compiler** for it! 

Our goal is to create a language that can solve all Advent of Code problems. To achieve this, we need to implement the following basic features:

* Conditional statements
* Loops
* Functions
* Data structures
* Basic input/output operations

Based on previous years' problems, it would be beneficial to also include:

* Built-in regular expression support
* Native hash map support
* Higher-order functions and function pipelining

These last three will make our life easier, but at this point it's hard to estimate how hard it will be to implement them.

## Interpreter or compiler?

There are several ways to implement a programming language. One approach is to interpret the code on the fly using a host programming language. Alternatively, we can compile the code into an intermediate representation, such as x86 assembly, LLVM IR, or bytecode, which can then be executed directly on a physical or virtual machine.

The main advantage of an interpreter is its agility and the ability to reuse existing standard libraries of the host language. This option is quite tempting overall. However, there is a significant downside: mediocre performance. I recall having to wait 20 minutes for some of my Haskell solutions in the past. There is a high chance that I will need to pivot from an interpreter approach very late in the **AoC**, which would be disastrous for me.
